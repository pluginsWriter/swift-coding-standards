## 4. 执行方式建议（剥离 ≠ 手工删出第二份）

**不要手工删出一个「发布版目录」。** 那正好是这工程最痛的一类事故：两份内容一旦分叉就是无报错的静默维护偏差。正确做法是**白名单导出**——正身永远是唯一真源，发布树是可重复生成的构建产物。

但这里有个必须先解决的**结构性冲突**：目前 `git` 就初始化在**正身目录里**，而发布要的是「剥过的树」。两种走法：

| 走法 | 做法 | 代价 |
| --- | --- | --- |
| **(i) 推荐** | `git` 移到发布侧：新建发布树目录并持有 `.git`，由 `scripts/export_public.sh` 从正身生成；正身不含 `.git`（纯内容） | 正身失去 `git log` 能力；导出脚本成为发布唯一入口 |
| (ii) 正身持有 git + 发布分支 | 用 `git commit-tree` 造无父提交 push 到 `main` | `main` 与正身工作树不一致，极易误判，不推荐 |

配套纪律（导出脚本里要断言，不能靠人记）：
1. 三个维护脚本与附录 C **同进同出**（否则发布包自检 FAIL，见 0.3）
2. 导出树里必跑一次「剥离后一致性检查」，通过才允许推送
3. 剥离产物必须 amend + force push **重写那唯一一次提交**，不能追加「擦除提交」（旧文本仍留在历史里）
4. `.workbuddy/` 与 `.DS_Store` 继续排除（既有规矩，已固化在 `.gitignore`）

### 断言逼出来的三个真问题（都是首版漏掉的）

1. **清单低估了 C 层**：首版只把迭代史当成附录 C 的问题，实际它有 11 处分布式散落（见 C-8），
   另有内部评审编号 2 处（见 C-9）。**是断言报「推翻 / 动因 仍有残留」才顺藤查出来的** ——
   说明「禁词扫描」这类断言的价值不在于通过，而在于它每次都能指出我还漏了什么。
2. **`run_awk` / `run_sed` 用 `mv` 替换文件会丢可执行位**（`755` → `644`）。由「可执行位断言」抓出。
   修法：变换前记下 `stat -f %Lp`，`mv` 后 `chmod` 还原。
3. **awk 多吃一行把脚本改成语法错误**：`remediate.sh` 的评审编号注释只占 2 行，我按 3 行写
   （`getline; getline` 两次），于是吃掉紧随其后的 `if [ -n "$DIRS" ]; then`。
   **这一条断言全绿也没抓到** —— 内容类断言查不出「文件结构被改坏」。
   修法有两个：把 `getline` 次数写对；**并在断言里加 `bash -n` 逐个检查脚本**（这条比前者更重要）。

### 方法论教训（可复用到任何「生成产物」的场景）

- **内容断言 ≠ 产物可用**。禁词、行数、锚点都能过，脚本照样可能是语法废的。
  凡导出产物里含可执行文件，**必须独立跑一次可执行性检查**（`bash -n`、或在临时目录真跑一次）。
- **校验函数本身也要被校验**：首版禁词模式把全角字符写进 `[...]` 字符类
  （`[（(][CD][0-9]+[（(]`），实测同一条正则**在 `grep -r` 与 stdin 下结论不一致**。
  改为字符类只用 ASCII、边界另加一个非标识符字符，并先对全量跑一遍确认无假阳性（`SC2206` 这类
  shellcheck 编号很容易被误判成评审编号）。
- **模式串里未转义的 `*` 会让 sed 静默不匹配**：`**` 在 BRE 里是「零个或多个 `*`」而不是两个字面星号，
