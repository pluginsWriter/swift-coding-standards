## 3. 用户既定的硬约束（后续不得擅自放宽）

1. **命名只针对「读不懂」，不针对「不眼熟」。**
   `normalize` / `reserve` / `perform` / `flight` / `generation` / `u16` / `blockWrites` 等
   中文开发者常用词**明确可接受，不得要求重命名**。只改三类：生僻词、自造缩写与单字母、
   对象或返回值无从判断。判据只有一条：**遮住定义只看调用点，陌生人能否说出这行在做什么**。
   → 完整词表唯一权威：`references/naming-antipatterns.md` 第 0 节（其余位置只引用，禁止复制）。
2. **人工排版与工具排版同等有效。**
   `swift format --in-place` **不是提交前必做动作**；钩子与 CI 只做 lint，禁止自动改写源码。
   手动断行/对齐必须被保留（`.swift-format` 的 `respectsExistingLineBreaks` 不得关闭）；
   局部豁免用 `// swift-format-ignore`。只有四类必须改：分号、块内多语句压行、`defer{`、
   关键字与花括号之间缺空格。
3. **缩进与行长：全工程统一 4 空格 / 120 列**，并开启 `indentSwitchCaseLabels` 与
   `indentConditionalCompilationBlocks`（2026-09-11 决定，推翻 09-10 的 2 空格 / 100 列）。
   适用**全部嵌套构造**，不只 switch。存量工程一次性全量重排，不做两段式过渡。
4. **不要为规范而规范**：规则写成「怎么判断」而不是冗长穷举；`-ed`/`-ing` 分词这类对
   非母语读者更难懂的约束不采用；泛化动词不强制规范化。
5. **严禁把格式修改与逻辑修改放进同一个提交**；禁止为通过检查而放宽阈值；
   重命名 public API 先写 ADR。
6. **默认生效 ≠ 擅自批量整改**：风格判定默认遵循规范，但大规模重命名/格式化仍须用户批准。
7. 代码注释与文档用简体中文，标识符用英文。

## 4. 关键技术坑（都是实测踩出来的，别重复踩）

| 坑 | 事实 | 应对 |
| --- | --- | --- |
| 并行 Edit 同文件 | 会「报成功但未落盘」，改动静默丢失 | 同文件**串行编辑**，改完 grep 逐条核验 |
| `swift format lint` 输出 | 走 **stderr**；且重复输出约 **3.5 倍** | 不要 `2>/dev/null`；必须 `sort -u` 去重 |
| 无 `.swiftlint.yml` 采基线 | opt_in 规则完全不生效，`print(value!)` 报 **0 条** | 采基线前先确认配置存在 |
| `.swiftlint.yml` 的 `included` | 相对**配置文件所在目录**解析；目录不存在时**静默空扫**报假 0 | Xcode 工程必须显式 `--dirs`，并同步改 `included` |
| `swiftlint lint` 无输出 | ≠ 达标：`unused_import` 一类规则要走 `swiftlint analyze` | 终检加 `--strict` |
| BSD sed 分组+交替正则 | 解析失败 | 改用 awk |
| macOS `awk length()` | 数的是**字节**不是字符 | 中文场景别用它量长度 |
| macOS `/bin/bash` 3.2 | `set -u` 下变量名紧跟全角标点，标点首字节被并入变量名 → unbound variable | 一律写 `${var}` 花括号形式 |
| WorkBuddy 是否跟随软链 | **跟随**（`cli/dist/codebuddy.js` 的 `isDirectoryEntry`/`isFileEntry` 走 `stat`） | 正身放 `~/.agents/skills`，另两处软链即可 |
| `description` 改动生效时机 | WorkBuddy **启动时**读取 | 改 description 后需**完整重启**，只开新窗口可能仍用旧缓存 |
| git 沙箱 | `index.lock` 死锁 | git 写操作需脱离沙箱 |
